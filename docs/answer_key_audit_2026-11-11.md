# 2026-11-11 · MathHint 전체265 정답표 검증 및 재채점

## 결과 요약

전체 265문항(학습185/테스트80)을 Gemini API의 완료 여부와 무관하게 점검했다.

- 원본 메타데이터 정답(answer_text)과 해설의 [정답] 표기는 265/265 일치한다. 이 사실만으로 답의 옳음을 보증하지 않는다.
- 문제 보기 또는 주관식 정답과 해설 마지막 계산값을 대조하여 **수치 비교 262개 일치 / 1개 불일치**를 확인했다.
- ㄱ/ㄴ/ㄷ 판단형 2개(diff_1_049, trig_2_012)는 수치 추출 대신 논리·계산을 별도 검토하여 원래 정답이 맞음을 확인했다.
- **독립 검산으로 확인된 정답표 오류는 1개: trig_1_010의 ④ → ②.** 이번 검토에서 추가로 확정된 정답 충돌은 없다.
- 이 점검은 265개 전체 해설의 중간 논리를 모두 독립적으로 증명한 검사가 아니다. 동일한 오답이 해설 끝과 답안표에 함께 기록된 경우 등은 발견하지 못할 수 있다.
- 새로운 Gemini API 호출 0회. 현재 전체265 실험은 1,060회 계획 가운데 **515개 성공, 545개 미완료**다.

## 검증 사례: trig_1_010

원문 문제: π/2 < t < π에서 5x²+x+k=0의 두 근이 sin t, cos t일 때 k tan t를 구한다.

원본 [정답]은 ④(12/5)이지만, 원본 해설의 마지막 계산값은 9/5이며 보기 ②에 해당한다.

근과 계수 관계에서 sin t + cos t = -1/5, sin t cos t = k/5. 따라서

(sin t + cos t)² = 1 + 2 sin t cos t = 1/25,

sin t cos t = -12/25, k = -12/5.

t가 제2사분면이므로 sin t = 3/5, cos t = -4/5, tan t = -3/4.

결국 k tan t = (-12/5)(-3/4) = **9/5 = ②**. 답안 번호 ④는 명확한 원본 오류다.

원본 HML 및 data/processed/metadata.json, data/processed/solutions/trig_1_010.txt는 덮어쓰지 않고, **data/curation/answer_key_corrections.json**에 보정 내용을 등록했다.

## 수치 대조에서 제외하고 수동 검토한 판단형 2개

- **diff_1_049: ⑤ (ㄴ, ㄷ).** x(t)=t³−t²−t+1이면 x(1)=0으로 ㄱ 거짓. 속도 v(t)=3t²−2t−1=(t−1)(3t+1)이어서 v(1)=0, ㄴ 참. t>0에서 속도 부호가 t=1 전후에 바뀌고 가속도 6t−2는 t=1일 때 4이므로 ㄷ 참.
- **trig_2_012: ⑤ (ㄱ, ㄴ, ㄷ).** tan(3πx/2)−sin(2πx)의 기본주기는 2, 2π+cos(2πx)sin(4πx/3)은 곱→합 전개에서 sin(10πx/3), sin(2πx/3)의 조합이어서 기본주기 3, sin(πx)−|cos(3πx/2)|의 기본주기는 2. 원본 키 ⑤와 일치.

## Codex가 후속 작업 시 지킬 점

1. 이 문서, data/curation/answer_key_corrections.json, AGENTS.md부터 읽는다.
2. 새로운 정답표 충돌을 발견하면 문제 원문·원본 해설·독립 계산 또는 반례를 확인하고 **원본 번호/정정 번호/보기 수치/문항 ID/출처 파일/근거**를 레지스트리에 보존한다.
3. 원래 raw/processed·원본 자동채점·API 응답·요청·해시·분할·모델·어휘를 보존한다. 과거 데이터의 의미를 조용히 바꾸지 않는다.
4. 보정 정답을 실제 지표로 사용할 때는 **정정 기준 결과**라고 명시하고, 원본 기준과 함께 볼 수 있어야 한다. 이후 미완료 API가 재개될 때 정정 결과만 보고서로 다시 계산한다.
5. 응답이 없는 545개 요청을 0토큰이나 오답으로 처리하지 않는다. 향후 새 API 호출이 성공해도 키 변경만으로 기존 80개 응답을 다시 호출하지 않는다.
6. 자동 숫자 비교는 모든 풀이의 정확성 증명이 아니다. 특히 원본 해설에 중간 논리 오류가 있거나 비수치형 판단인 경우 별도 확인이 필요하다.
7. 테스트80 풀이 오류 의심 22건(이 중 최종 답은 맞은 것 18건)은 **정답표 오류와 별도**로 관리한다. 오류 의심은 검증 완료가 아니다.
8. 정정 로직을 바꾼다면 테스트를 실행하고 원본 결과 SHA·사용량·응답 출처가 바뀌지 않았는지 점검하며, 수정 및 검증 결과를 기록한다.
9. gemini_full265/preservation_manifest.json은 약 3,500개의 과거 파일 해시를 고정한다. 보호 파일(루트 AGENTS.md, data/README.md, 과거 모델·Gemini 보고서 코드 및 결과 등)은 이 실험의 검증을 깨뜨리지 않도록 원본을 유지한다. 새 정정 파일과 문서는 별도 경로에 쓴다.

## 해석의 한계

이번 점검에서 새로 발견된 **확정 정답표 충돌 0건**이라는 사실은 정답표의 나머지 264문항이 모두 독립적으로 증명됐다는 의미가 아니다. 전체 해설의 논리·풀이 오류에 대한 완전 검증은 향후 별도 과정이다. API가 생성되지 않은 문항의 Gemini 답변은 아직 존재하지 않으므로 수학 풀이 오류를 검사할 수 없다.


## 2026-11-12 후속 정정: 실제 오답이지만 자동채점 불가로 표시된 응답

사용자와 연구의 최종 성능 지표는 **API가 성공해 최종 답을 실제로 출력했다면 그 답이 맞았는지** 평가해야 한다는 점을 명확히 했다. 자동 채점기가 읽지 못했다는 이유만으로 항상 정답/오답을 단정하지는 않는다. 다만 원문 응답을 검토해 수학적으로 잘못된 최종 답임이 확인되면 **오답으로 반영**한다.

- 문항: **trig_1_044**, 조건 **B (선형회귀 힌트)**, **학습185/전체265**에 속함
- 원본 정답: **③ (13개)**
- Gemini 실제 제출: **12개**. 선택지에 없는 수를 최종 답으로 명시했으며 문제의 최댓값 점을 누락함
- 기존 자동채점 결과: **null/채점 불가**
- 검토 후 정정된 결과: **False/오답**
- 검산: 첫 구간 0≤x<1에서 y=4인 점 1개, y=5·6 각각 2개, y=7인 점(x=1/2) 1개로 **6개**. 둘째 구간 1≤x<2에서 y=1·2·3 각각 2개, y=4인 점 1개로 **7개**. 따라서 **13개(③)**.
- 원문 근거: results/final_experiment_2/gemini_full265/case_reports/trig_1_044.md
- 독립 검토 기록: data/curation/answer_response_reviews.json

이 정정은 정답표 오류 trig_1_010과 **별개**로, 원본 API 성공 기록·출력 전문·원본 null 채점 결과는 그대로 남겨 두었다.

정정 코드 mathhint_analysis/VerifiedAnswerKey.py는 검증된 개별 응답의 수정 근거와 문항 ID·조건·원래 응답 텍스트를 검증한 뒤, 원본 자동채점 null을 유지하면서 파생 결과에만 False를 기록한다. 대응 McNemar 분석의 B 포함 분모도 이에 따라 갱신한다. 정정 전후 성적 모두 results/final_experiment_2/gemini_full265/key_corrected/에 있다.

**재현:** python -m mathhint_analysis.VerifiedAnswerKey. API 호출 또는 모델 재학습 없음. 새 자동 테스트는 tests/test_verified_answer_key.py에 추가했으며 실제 Python 테스트 실행 여부는 별도로 검증해야 한다.
