# 저장소 사용 여부 조사

이 문서는 **정리 전 조사**이며 실제 삭제 내역을 대신하지 않는다. 조사 당시 파일별 역할·참조·보존 판단은 [repository_inventory.csv](repository_inventory.csv)에 있다. Git 관리/미관리/무시 파일을 구분했고 `.git` 내부는 제외했다. `.env` 내용과 해시는 수집하지 않았다. 병렬 구현으로 새 파일이 생길 수 있으므로 최종 정리 후 실제 Git diff와 함께 대조한다.

## 확실한 정리 후보

- `examples/bow_sample.txt`, `examples/bow_sample_2.txt`: 현행 실행·테스트의 참조가 없는 초기 연습 자료다. 테스트는 이미 각자의 임시 문자열을 사용한다. 폴더 전체 삭제 가능.
- `.vscode/settings.json`: 개인 conda 도구 선택이며 연구 재현과 무관하다.
- HWPX 전용 기능군 `mathhint_preprocess/{__main__,hwpx,models,segment,export}.py`, `scripts/validate_latex.py`, `tests/test_hwpx.py`, `tests/test_export.py`: 현재 HML 데이터 준비에서 호출하지 않는다. 이 기능군은 서로 의존하므로 함께 정리하고 `pyproject.toml`의 `mathhint-preprocess` CLI·README/패키지 설명을 갱신한다. **`hml.py`, `equations.py`와 두 핵심 테스트는 계속 필요하다.**
- `requirements-learning.txt`: pyproject의 `[learning]`과 같은 네 패키지다. 설치 안내를 `pip install -e '.[learning]'`으로 통일하면 삭제할 수 있다.
- Git에서 무시하는 `.upstream_tree.json`, `.missing_blobs.json`, `__pycache__`: 재현에 필요 없는 캐시다. 이 조사는 실제 삭제를 수행하지 않았다.

## 의존 관계를 먼저 풀어야 하는 통합 후보

- `GoogleAPI.py` 단일 문제 보조 실행과 `tests/test_solver.py`는 최종 세 조건 실행과 역할이 겹친다. 최종 SDK 경계 테스트가 동일 보호 기능을 제공하는 것을 확인한 뒤 제거할 수 있다.
- `BuildFrequencyVectors.py`는 임의 TXT 폴더를 처리하는 선택 도구이며 `PrepareDataset.py`의 고정 데이터셋 생성과는 진입점이 다르다. 최종 연구에 필요하지 않다면 `tests/test_frequency_vectors.py`의 중요한 어휘/수식 오류 검사를 현행 경로에 옮긴 뒤 삭제할 수 있다.
- `RunTraining.py`의 기존 통합 실행은 새 4단계 비교로 대체할 수 있으나 `test_fixed_training.py`가 공통 함수를 가져온다. 함수를 핵심 모듈로 옮기거나 테스트 import를 바꾸기 전에는 파일을 삭제하지 않는다.
- `AnalyzeExperiment.py`의 통계 함수는 `AnalyzeThreeWay.py`가 실제로 사용한다. 2조건 보고서 진입점을 정리해도 공통 통계는 보존한다.
- `BuildComparisonViewer.py`는 기존 2조건 전용이다. 최종 정적 자료가 열람 기능을 대체하고 `test_experiment_report.py` 참조를 정리한 뒤 통합할 수 있다.
- `GenerationReport.py`는 `CompareGeneration.py`의 실제 import 대상이다. 현재 import를 남겨 둔 채 삭제하지 않는다.

## 보존 및 복구 규칙

- 원본 HML 6개, 번호 대조표·그림 제거 기록·수식 전사 46건, 265개 문항/해설/분류, 고정 분할185/80, 학습 전용 어휘346/431, 최종/기존 학습 모델과 설정을 보존한다.
- 기존 `results/model_comparison_2026-11-07/03_Gemini비교/`의 원본160개 응답과 입력·검토·정답표 충돌 근거, `provenance/`의 실제 생성 당시 설정/코드/응답을 보존한다. 기존 실험의 원본을 덮어쓰지 않는다.
- 기존 PDF·그래프 등 중복 표시 자료는 최종 통합 여부를 확인한 후에만 정리할 수 있다. 원본 응답/모델/수치와 같은 것으로 취급하지 않는다.
- 삭제 전에 부모 작업자가 Git 체크포인트/복구 브랜치를 만들고 원격 반영을 확인해야 한다. 미추적 파일의 복구는 Git 커밋만으로 보장되지 않는다.
- `docs/checkpoints/cancelled_before_final.zip`은 미추적 초안을 포함한 취소 작업 복구본이다. 최종 통합 후 Git 이력으로 충분히 복구되는 것을 확인하면 현재 트리의 중복 ZIP을 정리할 수 있다. 비밀 설정은 복구용으로 Git에 넣지 않는다.

## 데이터 검증 결과

[검증 원본 JSON](data_validation.json)에 실행 시점·데이터/코드 해시·42개 검사가 저장되어 있다. 원본 HML에서 임시 폴더로 재생성한 전처리801개와 벡터7개 파일은 저장된 데이터와 **808/808 바이트 동일**했다. 원본 폴더는 수정하지 않았다. 학습185개·테스트80개는 중복이 없고 모든 벡터 행은 분할 ID 순서와 일치한다. 실제 빈도는 모두 비음수 정수다. 학습 전용 어휘는 문제346개·해설431개이며 테스트에만 존재한 토큰20개·31개는 어휘에 포함되지 않았다.

과목 라벨은 `curriculum`이며 `subject`는 원본 자료군(미분/삼각함수)이다. 고유 경로 기준 전체/학습/테스트 개수는 과목2/2/2, 단원8/8/8, 세부단원25/25/17, 유형70/70/42다. 최종 군집 수는 학습 집합의2·8·25·70개로 자동 도출해야 한다.

이 검사는 데이터 처리의 재현성과 ID/어휘 대응을 검증한다. 모든 문제의 수학적 정답을 새로 증명한 것은 아니며, 모델 학습 경로와 Gemini 입력 누출 감사는 별도 단계다.
