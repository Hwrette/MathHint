### 출력이 줄어든 대응에서 정답·풀이 판정은 어떻게 달라졌는가?

같은 문항·같은 반복 번호의 두 API 수신 응답 중 출력 토큰 차이가 음수인 쌍만 살펴본다. 사용량 미제공 쌍은 제외하며, 잘린 응답 등 최종 답이 없는 경우는 오답이 아니라 미판정으로 남긴다.

|---|---:|---:|---:|

|B-A|6/8|2/2/2/0|0/2/4/0|

최종 답의 개선/악화는 오답→정답/정답→오답, 풀이의 개선/악화는 오류 의심→타당 가능/타당 가능→오류 의심을 뜻한다. ‘동일’은 판정 상태가 같다는 뜻이며 답 문자열·풀이·오류 단계가 동일하다는 뜻은 아니다. 각 행의 네 판정 횟수 합은 출력 감소 쌍 수와 같다.
같은 5문항을 조건당3회 반복한 설명 통계다. 출력이 짧아진 쌍만 사후 선택한 이 표로 토큰 감소가 정답이나 수학적 타당성을 바꾼 인과효과를 추정하지 않는다.


**출력 제한·불완전 응답도 연구 결과에 포함했다.**
- `trig_1_040/F/반복1`: `truncated_response`, 실제 출력 8188·전체 8557토큰. 최종 답 미완성 여부와 풀이 오류는 따로 기록했다.
- `trig_1_040/F/반복2`: `truncated_response`, 실제 출력 8188·전체 8557토큰. 최종 답 미완성 여부와 풀이 오류는 따로 기록했다.

큰 사용량을 가진 응답은 평균·SD를 크게 바꿀 수 있다. 이를 제외하거나 같은 반복을 다시 생성하지 않았으며 문항별 그림의 개별 반복 점과 최소~최대에서 직접 확인할 수 있다.

E-A의 변화가 관측되어도 모든 차이를 지시문으로 설명할 수 없고, F-D의 변화가 관측되어도 출처 강조의 인과효과라고 확정할 수 없다. D/F는 동일한 토큰·빈도 JSON을 유지했지만 제목이 바뀌며, 표본은 조건당3회뿐이다.

## 실행·재개·감사

```bash
python -m mathhint_solver.final_experiment_2.final_followup preflight
python -m mathhint_solver.final_experiment_2.final_followup generate
python -m mathhint_solver.final_experiment_2.final_followup report
python -m mathhint_solver.final_experiment_2.final_followup verify
```

report와 verify는 저장 자료만 읽고 API 호출·모델 학습을 시작하지 않는다. generate는 이미 응답을 받은 같은 문항·조건·반복을 잘림 여부와 관계없이 재호출하지 않는다. API 제한으로 중단되면 정확한 미수신 목록과 재개 명령을 [state.json](state.json)에서 확인한다.

동결된 config.json의 cache_policy에는 관측 전의 ‘success’ 표현이 해시 보존을 위해 남아 있다. 첫 잘림 응답을 관측한 뒤 반복 슬롯을 다시 뽑는 선택 편향을 막도록 **실제 API 응답을 받은 슬롯은 정상 종료 여부와 관계없이 한 번의 관측으로 종료**하는 정책을 명시했다. 현재 완료 수와 미수신 목록은 state.json의 completed_requests/api_response_count를 기준으로 읽는다. 모델·프롬프트·출력 상한·토큰은 바꾸지 않았다.

통신 정책 변경: 117개 응답을 보존한 뒤 HTTP/서버 응답 대기 상한을 180초에서 300초로 늘렸다. 실제 HTTP504 및 읽기 타임아웃에 따른 전달 대기 변경이며, SDK의 X-Server-Timeout에도 반영된다. 문제·힌트·모델·temperature·thinking·최대 출력8192는 그대로이고 이미 받은 정상·출력 제한 관측을 다시 뽑지 않았다. 요청별 대기 상한은 SDK 캡처·응답·실행 이력에 따로 남긴다. 이 실행 시점/통신 정책 차이도 작은 반복 실험의 한계로 고려한다.

[설정](config.json) · [동결된 실제 프롬프트](frozen_prompts/) · [신규 응답 원문](responses.jsonl) · [검토 상태 CSV](review/status.csv) · [검증](validation.json) · [실행 기록](execution_runs/)

API 수신 응답의 수학 검토 상태: `{'appropriate': 45, 'inappropriate': 72}`. 과거 판정을 새 응답에 그대로 복사하지 않았고 검토 근거는 새 응답 SHA와 실제 인용으로 연결한다.

실제 상위 토큰은 최대20종이다. 기존 D/trig_2_022는 양의 빈도 좌표가19개여서19종을 그대로 재사용했으며20번째 토큰을 만들지 않았다.

## 해석의 범위

3회 표본 SD는 **ddof=1**이다. 사용량이 제공된 API 수신 응답이0개면 평균·최소·최대·SD는 —, 1개면 SD는 —다. 미제공은 null/—이며0으로 채우지 않는다.
**출력 제한(MAX_TOKENS)·차단·빈 응답도 API 응답을 받은 한 번의 반복이다. 같은 반복을 다시 뽑지 않는다.** 잘린 응답의 실제 토큰은 사용량 평균에 포함하지만, 최종 답이 완성되지 않았다면 채점 보류로 남긴다. 설정된 토큰 상한을 실제 사용량 대신 넣지 않는다.
정답 횟수와 풀이 타당 가능 횟수는 별개다. 검토 보류를 오류로 간주하지 않으며 AI 보조 검토는 사람의 확정이나 형식적 증명이 아니다. 자기 수정 횟수는 일부 중간 오류의 명시적 수정을 뜻하며, 다른 오류가 남아 최종 오답·풀이 부적절과 함께 나타날 수도 있다.
같은 문항·같은 반복 번호를 대응시켰지만 조건 순서가 섞인 탐색적 비교다. 3회 모두 정답이어도 오류 가능성이 사라졌다고 주장하지 않는다.
고정 temperature0에서도 서비스 구현·실행 시점에 따라 응답이 달라질 수 있다. 같은 텍스트가 반복돼도 실제 신규 호출 여부는 실행·SDK 경계 기록으로 확인한다. 3회는 탐색적 재현 관찰이며 인과효과나 확정적 성능 순위를 뜻하지 않는다.
D/F는 원본 정답 해설의 토큰을 미리 제공한 오라클 진단이다. 문제 원문·모델·학습 모델·어휘·기존 응답은 변경하지 않았다. 추론/캐시 미제공은0이 아니며 전체 토큰에 임의로 더하지 않는다.
