# MathHint 고2 연구 최종 보고서

저장된 성공 응답 240/240개. 응답 확보 완료이며 검토 범위는 아래에 따로 명시한다.

## 1. 연구 목적 및 가설

수학 문제를 BoW 빈도 벡터로 나타내고, K-means로 교육과정 분류를 재현할 수 있는지, 선형회귀로 해설 빈도를 예측할 수 있는지, 그 정보를 LLM에 제공하면 풀이에 도움이 되는지 확인한다. 가설은 (1) 토큰 구성으로 일부 분류가 묶이고, (2) 예측 해설 토큰이 풀이를 보완하며, (3) 실제 해설 토큰과 비교하면 예측 오차와 표현 방식의 한계를 탐색할 수 있다는 것이다. 효과의 존재나 원인은 결과를 보기 전에 확정하지 않았다.

## 2. 데이터 구성과 전처리

그래프·그림 문제를 걸러낸 HML 6개에서 265문항을 확보했다. 고정 학습185·테스트80을 유지하며 ID·분류·출처는 메타데이터로, 문제와 해설은 별도 텍스트로 저장한다. 어휘는 학습 자료에서만 만들었고 문제346·해설431차원이다. 테스트 해설의 새 어휘는 추가하지 않았다. `subject`는 미분/삼각함수 자료군이고 실제 과목은 `curriculum`이다. 라벨 경로는 과목→단원→세부단원→유형을 포함해 동명이인을 합치지 않는다.

## 3. K-means 군집화 실험 방법

분류 단계마다 학습에서 고유 라벨 수를 계산해 k로 정했다. 원시 BoW의 유클리드 K-means와 L2 정규화 입력·정규화 중심을 쓰는 Spherical K-means를 비교한다. 반복100회·시드42~46의5개 재시작을 통제하며 각자의 학습 목적함수로 실행을 선택한다. 테스트의 라벨·ARI·NMI로 시드를 선택하지 않았다. 중심과 군집 대표 라벨은 학습에서만 계산한다. ARI는 우연 일치를 보정한 군집 유사도, NMI는 라벨·군집 사이 정보의 일치도다. 군집 번호 자체는 정답 라벨 번호가 아니다. 학습 다수 라벨 정확도는 보조 지표다.

## 5. 선형회귀 모델의 구조 및 실험 방법

문제346차원에서 해설431차원으로 가는 하나의 선형층(가중치·편향)을 MSE로 학습했다. 기존500epoch·Adam·학습률0.01·seed42 모델을 보존하고 동일한 가중치·데이터·출력임을 검증해 재사용한다. 테스트는 가중치 학습에 들어가지 않는다. 학습 평균 해설 벡터 기준선, 원시 실수 예측, 음수를0으로 바꾼 예측을 비교한다. 평가에는 정수 반올림을 하지 않는다.

## 6. 회귀 모델의 벡터 예측 성능

|방법|MSE ↓|MAE ↓|평균 코사인 ↑|
|---|---:|---:|---:|
|training_mean|3.559432|0.484312|0.798630|
|raw|3.356985|0.622918|0.820015|
|clipped_nonnegative|3.012478|0.485584|0.847980|

상위20토큰의 평균 공통 개수 14.062개, Precision@20 0.7031. 양의 값만 선택하고 동률은 고정 어휘 인덱스로 처리한다. 실제 양의 토큰이20개 미만인 문항 0개이며 Precision@20 분모는20을 유지한다. 선택된 예측 개수를 분모로 한 지표도 별도로 보존했다.

**관찰:** 음수 보정의 MSE는 학습 평균 기준선보다 15.37% 작았고 평균 코사인은 0.0494 높았다. MAE는 0.485584로 기준선 0.484312보다 약간 커서 모든 오차 지표가 개선된 것은 아니다.

예를 들어 `trig_2_016`는 코사인 0.9683·공통 토큰 18개인 반면 `trig_1_043`는 0.3685·8개다. 이 순위는 빈도 벡터의 유사도이며 수학적으로 중요한 개념을 맞혔다는 판정은 아니다.

코사인 유사도는 벡터 방향의 유사도이며 문제의 정답률이 아니다. 음수 보정은 BoW의 비음수 성질과 맞지만 빈도 예측 오차가 사라지는 것은 아니다. 공통 대수 기호·일반 표현의 높은 빈도가 수학적으로 필요한 순서·관계를 포착했다는 뜻도 아니다. [문항별 지표·상위 토큰](02_regression/question_comparison.csv), [실제·원시·보정 벡터](02_regression/vectors.json), [성공·실패 및 그래프](02_regression/analysis.md)를 함께 본다.

## 7. Gemini API 비교 실험 방법

테스트80문항에 A문제만, B예측 해설 상위20토큰, C실제 해설 상위20토큰을 제공한다. 요청 모델 `gemini-3.1-flash-lite`, temperature `0.0`, thinking `minimal`, 최대 출력 `8192` 및 시스템 지시·정답 평가를 통제한다. B/C는 동일한 고정 학습 어휘, 양수 토큰 선택·내림차순·동률 어휘순·소수3자리 표시·프롬프트 구조를 사용하며 정보 출처 설명만 다르다. 원시 예측값은 별도로 남긴다.

C는 정답 해설에서 얻은 정보가 포함되는 오라클 진단 조건이다. 정답에 직접 연결되는 토큰이 있을 수 있어 서비스 성능으로 해석하지 않는다. 고정 어휘·상위20으로 정보를 제한하므로 전체 해설을 준 것도 아니고 이론적 성능 상한도 아니다. 기존 A/B 응답은 설정·완성 입력 해시가 같은 경우에만 재사용한다. C는 이번 추가 실험이며 호출 날짜 차이 및 서비스 내부 변경 가능성은 남는다. API 직전 저장된 요청과 SDK 호출 인자는 [입력 감사](03_gemini/prompt_audit/)로 추적하고, 실제 모델 버전은 반환값 범위에서만 기록한다.

API usage의 입력·출력·추론·전체 필드를 그대로 보존했다. 전체 토큰에는 추론 등을 다시 더하지 않는다. 추론 미제공은 0이 아니다. 합계는 해당 조건 성공 응답 모두에서 값이 제공될 때만 표시한다.

|대응 비교|채점된 쌍|왼쪽만 정답|오른쪽만 정답|오른쪽−왼쪽|McNemar p|
|---|---:|---:|---:|---:|---:|
|A → B|80|2|1|-1.25%|1.0000|
|A → C|80|4|1|-3.75%|0.3750|
|B → C|80|2|0|-2.50%|0.5000|

전체 토큰이 미제공인 전송 시도(누적 보존 이력): A 36회 / B 0회 / C 1회. A/B의 이력은 재사용한 과거 실행이며 현재 추가 C 실행과 구분한다. 따라서 이 표의 성공 응답 합계를 모든 시도의 확정 소비량·청구 비용으로 해석하지 않는다.

실패 후 별도 실행에서 재요청한 문항: `diff_2_020` (누적 2시도). 성공이 이미 저장된 조건은 다시 요청하지 않았다.

신규 실험의 기록된 전송 시도 81회 중 실패 기록 1회, 전체 토큰 미제공 시도 1회다. 성공 응답의 합계는 비교할 수 있지만, 실패 시도의 사용량이 미확인인 경우 전체 청구 비용·소비량은 확정할 수 없다.
- `diff_2_020`: `ReadTimeout` (실행 1, 시도 1). 서버에서 처리가 끝났는지와 사용량은 응답이 없어 미확인이다. 재개 시 성공 응답을 중복 호출하지 않고 실패 문항만 제한적으로 다시 요청했다면 그 이력을 누적 보존한다.

McNemar 검정은 같은 문제의 정오답 차이에 대한 보조 분석이다. 계획된 세 비교에 다중 비교 보정을 적용하지 않았으며 채점된 쌍이 없으면 산출하지 않는다. 작은 정답 수 차이를 일반적인 개선으로 단정하지 않는다.



**관찰:** A와 B의 원본 정답 수는 78→77개다. 성공 응답에 보고된 전체 토큰은 51,820→68,615로 32.41% 증가했다. 이80문항의 결과에서 예측 힌트가 정답률을 높였다는 증거는 없으며 입력 토큰의 증가는 확인된다. 작은 차이의 일반화·원인은 확정할 수 없다.

**관찰:** 실제 해설 토큰을 제공한 C는 원본 정답표 기준 75/80개로 A보다 -3개, B보다 -2개 차이가 났다. 정답 해설에서 미리 얻은 정보를 주는 조건이므로 이를 일반적인 서비스 성능으로 비교하거나 원인 하나를 확정할 수 없다. 차이가 작고 문항당1회 생성이므로 예측 오차의 영향과 빈도 표현의 유용성을 탐색하는 참고 결과로 해석한다.

### 풀이 타당성

- A 문제만: 기존 동일 응답의 AI 보조 검토 재사용. 적절 76, 부적절 4, 불확실 0, 미검토 0. 사람의 확정 검토 0건.
- B 예측 상위20토큰: 기존 동일 응답의 AI 보조 검토 재사용. 적절 71, 부적절 7, 불확실 2, 미검토 0. 사람의 확정 검토 0건.
- C 실제 해설 상위20토큰: 신규 AI 보조 검토 적절 71, 부적절 9, 불확실 0, 미검토 0. [실제 인용·수학 근거](03_gemini/solution_review.json)를 확인한다. 사람의 확정 판정이 아니다.

C의 부적절 판정은 최종 답이 맞지만 표기·중간 논리에 문제가 있는 5건과 최종 오답이면서 풀이에도 문제가 있는 4건을 포함한다. 표기 오류·뒤에서 재계산한 오류·근거 부족·최종 오답의 error_kind를 구분해 기록했다. 따라서 9건을 모두 최종 오답이나 같은 심각도의 오류로 해석하지 않는다.

신규 C와 기존 A/B는 검토 시점·검토자가 달라 AI 검토 개수 차이를 엄밀히 통제된 성능 차이로 확정하지 않는다. 공식 교육과정 성취기준 전체와 대조하지 않아 교과 범위는 여전히 미확정이다.

기존 AI 검토는 조건을 알 수 있는 상태에서 작성되었으며 독립적인 블라인드 사람 평가가 아니다. 해시·인용 일치는 대상의 동일성을 확인할 뿐 판단의 수학적 정확성을 보증하지 않는다.



모든80문항을 같은 행에서 비교하는 [Gemini CSV](03_gemini/question_comparison.csv), [전체 분석](03_gemini/analysis.md), [조건별 실제 응답](03_gemini/responses.jsonl)을 제공한다. 풀이 타당성의 기존 AI 검토·미검토 범위는 Gemini 분석에 따로 표시했다. 최종 답과 풀이 평가를 합쳐 하나의 정확도로 부르지 않는다.

## 9. 실험에서 발견한 문제와 원인에 관한 가설

**확인한 사실:** 원본 정답표와 수학적 도출이 충돌하는 문항1개가 있다. BoW에는 토큰 순서·수식의 구조 관계가 저장되지 않는다. 예측 벡터에는 실제와 다른 빈도가 있고 상위20은 전체 해설의 일부만 남긴다. 최종 답이 맞아도 잘못된 중간 등식을 쓰는 기존 응답 사례가 있다.

**해석·가설:** 예측 힌트의 오차, 이미 강한 기본 모델의 높은 정답률, 자주 나오는 일반 토큰의 제한된 정보, 추가 정보가 만드는 혼란 등이 효과가 작거나 불안정한 이유일 수 있다. C가 B보다 좋아도 예측 오차만이 유일한 원인이라고 확정할 수 없고, C에서도 개선이 작아도 모든 빈도 표현이 무용하다고 결론낼 수 없다. 동일80문항 단일 생성 비교만으로 이러한 원인을 분리해 검증하지 못했다. 조건별 변동 사례는 [직접 분석 자료](04_case_studies/selected_cases.md)와 [ID 연결](04_case_studies/questions.md)을 본다.

## 10. 연구의 한계

- 학습185·테스트80의 작은 자료이며 일부 유형은 매우 적다. 그래프가 필요한 문제를 제외해 수학 문제 전체를 대표하지 않는다.
- 학습과 테스트를 분리했지만 이전 테스트 결과를 이미 본 후 후속 비교를 설계했다. 완전히 새로운 미관찰 최종 평가라고 주장하지 않는다.
- 각 조건 문항당1회 생성이다. temperature0도 모델 서비스의 완전한 결정성을 보장하지 않으며 반복 생성 분산을 측정하지 않았다.
- 정답 표기·자동 파싱의 한계와 원본 키 충돌이 있다. AI 보조 판정과 사람의 확정 판정을 구분한다.
- 풀이 검토에는 AI 판단의 오류·조건 인지 편향이 남고, 공식 성취기준과 전부 대조하지 않아 교육과정 적합성은 다수 미확정이다.
- C는 실제 정답 해설의 정보를 미리 주는 진단이며 실제 사용 시 제공할 수 있는 정보가 아니다. B/C 모두 학습 어휘 밖 토큰과 순서·수식 구조를 담지 못한다.
- 토큰 사용량은 API의 제공값이며 미제공 추론 값을0으로 추정하지 않았다. 과거 A/B 재사용과 신규C의 실행 시점 차이가 있다.

## 11. 최종 결론 및 후속 연구 방향

이번 연구는 별도의 단순 모델에서 얻은 특징을 LLM에 간접 제공하는 방법을 실제 문항·벡터·응답으로 추적 가능하게 비교했다. 관찰한 점수 차이와 토큰 비용을 함께 보아야 하며 작은 차이만으로 일반적인 성능 개선이나 실패를 확정하지 않는다. BoW 군집·회귀는 일부 빈도 관계를 분석하지만 토큰 순서와 수식의 의미 관계를 직접 표현하지 못한다.

후속으로 다층 신경망 회귀를 고려할 수 있으나 이번 결과만으로 필요성이나 향상을 단정하지 않는다. 실제 해설 조건과 예측 조건의 차이를 먼저 해석해야 한다. 제한된 데이터에서는 작은 모델, 학습 집합 내부 검증 또는 교차검증, 가중치 규제·조기 종료로 과적합을 관리하고 학습/검증 차이를 확인한다. 최종 테스트를 반복적으로 하이퍼파라미터 선택에 쓰지 않으며 단순 평균·선형 기준선보다 개선되는지 검증해야 한다. 층을 늘려도 BoW에서 잃은 순서·수식 구조가 자동 복구되지는 않는다.

고3 연구는 사전학습 LLM의 문맥·순서 관계를 다루는 트랜스포머를 이해하고 디코딩 제약으로 생성을 직접 제어하거나 Lean으로 형식화된 결과를 검증하는 방향으로 확장할 수 있다. 트랜스포머를 처음부터 대규모 학습할 필요는 없다. 이는 빈도 표현의 실패를 미리 단정한 교체가 아니라 간접 특징 제공의 효과를 살핀 뒤 생성의 직접 제어·검증을 탐구하는 연결이다. 디코딩 제약은 잃은 입력 정보를 복원하지 않으며 Lean의 증명 성공이 고교 교육과정 적합성까지 보장하지 않는다. 이번에는 이 후속 모델·파이프라인을 구현하지 않았다.
